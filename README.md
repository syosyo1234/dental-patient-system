# 患者管理システム

小規模な歯科クリニック向けの、患者基本情報・来院記録・診療費を管理する Web アプリケーションです。

> **ご注意**
> 本システムは localStorage を使用しており、サーバー・ユーザー認証・正式なセキュリティ管理の仕組みを持っていません。
> そのため、**架空のデータによる開発・テスト専用**です。実在する患者の個人情報や診療記録の保存には使用しないでください。
> 同梱のデモデータ（氏名・住所・電話番号・診療内容など）はすべて架空のものです。

---

## 1. システム概要

受付業務でよく使う、次の流れを想定して作っています。

1. **初診時**：「新規患者登録」で患者基本情報を登録し、患者詳細画面から初回の来院記録を追加します。
2. **再診時**：患者一覧で氏名または患者IDを検索し、患者詳細画面で「＋ 来院記録を追加」を押します。基本情報を再入力する必要はありません。
3. 来院回数・累計診療費・最終来院日は、来院記録から自動で計算されます。

サーバーは不要で、`index.html` をダブルクリックするだけでブラウザ上で動作します。

## 2. 使用技術

| 項目 | 内容 |
|---|---|
| 画面 | HTML5 |
| デザイン | CSS3（CSS 変数、Flexbox、CSS Grid、メディアクエリ） |
| 処理 | JavaScript（フレームワーク不使用。ES modules・fetch 不使用） |
| データ保存 | ブラウザの localStorage（JSON 形式） |
| 動作環境 | Google Chrome / Microsoft Edge / Safari / Firefox の最新版（PC・タブレット） |

### ファイル構成

```
dental-patient-system/
├── index.html   画面の構造（患者一覧・患者フォーム・患者詳細・来院記録フォーム）
├── style.css    デザイン
├── app.js       アプリケーションの処理
├── data.js      デモデータ（架空の患者 8 名・来院記録 28 件）
├── questionnaire.html  初診問診票（患者さんがスマートフォンで開く画面）
├── questionnaire.css   問診票のスマートフォン向けデザイン
├── questionnaire.js    問診票の処理（入力チェック・確認画面・送信）
├── questionnaire-common.js  問診票の共通処理（保存先・回答の表示方法。患者側と管理側の両方で使用）
└── README.md    本書
```

`index.html` は `data.js` → `questionnaire-common.js` → `app.js` の順に読み込みます。
`questionnaire.html` は `style.css`（共通デザイン）・`questionnaire.css`・`questionnaire-common.js`・`questionnaire.js` だけを読み込み、患者データ（`data.js`）や管理機能（`app.js`）は読み込みません。

## 3. 主な機能

### 患者一覧
- 患者ID・氏名（フリガナ）・生年月日・電話番号・初診日・最終来院日を一覧表示
- 最終来院日の新しい順に表示
- 氏名・フリガナ・患者IDで検索（空白の有無、英字の大文字・小文字は区別しない）
- 登録患者数・検索結果数の表示
- 「デモデータに戻す」（確認後、初期データに戻す）

### 新規患者登録・基本情報の編集
- 患者ID（P0001 形式）を自動採番。重複しないことを確認して採番
- 初診日は当日を初期表示

### 患者詳細
- 患者基本情報（年齢は生年月日から自動計算）
- 来院回数・累計診療費・最終来院日の表示（来院記録から自動計算）
- 来院履歴（来院日の新しい順）

### 来院記録の追加・編集
- 来院日（当日を初期表示）・主訴・症状・診療内容・担当医・費用・備考
- 表示中の患者IDに自動で紐付け
- 記録ごとに独立した記録ID（V0001 形式）を持ち、編集時は記録IDで対象を特定
- 担当医は過去の入力内容から候補を表示

### 来院記録の削除
- 来院記録の編集画面の一番下にある「この来院記録を削除」から1件ずつ削除（新規追加画面には表示しない）
- 確認画面で来院日・診療内容・費用を表示
- 削除後、来院回数・累計診療費・最終来院日は自動で再計算
- 削除した記録の記録IDは、別の記録に再利用しない

### 入力チェック（エラーは日本語で各項目の下に表示）
| 項目 | チェック内容 |
|---|---|
| 氏名 | 必須（外国籍の患者にも対応するため、文字の種類は制限しない） |
| 生年月日 | 日付形式、未来日不可 |
| 電話番号 | 数字とハイフンのみ（全角数字は自動で半角に変換） |
| 初診日 | 必須、日付形式、生年月日より後 |
| 来院日 | 必須、日付形式、未来日不可、生年月日より後 |
| 費用 | 必須、0 以上の整数（「¥」「円」「,」、全角数字は自動で除去・変換） |

### 初診問診票（questionnaire.html）
患者さんが問診票を入力する画面です。管理画面とは別のページで、患者一覧・他の患者の情報・来院履歴・管理機能は表示されません。

- 画面の流れ：① 入力 → ② 確認 → ③ 送信完了（「問診票の送信が完了しました。受付スタッフにお声がけください。」）
- 質問項目：基本情報／来院目的／現在の症状／ご希望の診療・サービス／通院時間帯・治療費／来院のきっかけ／健康状態（アレルギー・服用中のお薬・持病・配慮してほしいこと）／自由記入
- できるだけ選択式（複数選択はチェックボックス、1つだけ選ぶ質問はラジオボタン）
- 「その他」「あり」を選んだときだけ、詳しい内容の入力欄を表示
- 生年月日は「年」「月」「日」のプルダウンで選択（スマートフォンではスクロールで素早く選べる。月に合わせて日の選択肢が 28〜31日に変わる）
- 「特に症状はない」「特に希望なし」を選ぶと、同じ質問の他の選択肢は自動で外れる
- 必須項目：氏名、来院目的（1つ以上）、アレルギー・服用中のお薬・持病の有無（「あり」の場合は内容も必要）
- 入力エラーは画面上部にまとめて表示し、該当する質問を赤く表示
- 送信後は入力内容を画面から消去（同じ端末を次の人が使っても見えないように）
- URL の最後に `?demo=1` を付けて開くと、テスト用の架空データを入力するボタンが表示される

### 問診票受付（管理画面）
患者一覧の右上の「問診票受付」から、送信された問診票を確認・登録します。未確認の件数はボタンに表示されます。

- 一覧：受付日時・氏名・来院目的・受付状況（未確認／確認済み／患者登録済み）を新しい順に表示
- 問診票を開くと、受付状況が「未確認」→「確認済み」になる
- **患者として登録**：問診票の基本情報（氏名・フリガナ・生年月日・性別・電話番号・住所）から新しい患者を作成し、患者IDを自動発行
  - 初診日：問診票の受付日
  - 備考：アレルギー・服用中のお薬・持病・配慮してほしいこと
  - 性別「回答しない」は「未選択」として登録
- **重複の確認**：同じ氏名・生年月日の患者がいる場合は警告を表示し、「この患者に紐付ける」で既存の患者に問診票を紐付けられる（患者の基本情報は変更しない）
- 登録・紐付けした問診票は「患者登録済み」になり、患者詳細の「初診問診票」欄からいつでも確認できる（来院履歴とは別に管理）
- 同じブラウザの別のタブで問診票が送信されると、件数と一覧が自動で更新される

**仕組みと制限**：問診票は、患者管理システムと同じ**その端末のブラウザの localStorage**（`dentalClinic_questionnaires`）に保存されます。
そのため、**問診票と管理画面を同じ端末・同じブラウザで開いた場合のみ**反映されます（例：受付のパソコンやタブレットで患者さんに入力してもらう）。
患者さん自身のスマートフォンから送信した内容をクリニックのパソコンに届けるには、共有データベース（Supabase など）とログイン認証・アクセス制御が必要です。

### データ保護
- localStorage の読み書きはすべて `try / catch` で処理
- 読み込みに失敗した場合はエラーを表示し、既存データを上書きしないよう保存を停止
- 保存に失敗した場合は、画面上の変更も元に戻す

## 4. データ構造

localStorage に次のキーで保存します（値は JSON 形式）。

| キー | 内容 |
|---|---|
| `dentalClinic_patients` | 患者基本情報の配列 |
| `dentalClinic_visits` | 来院記録の配列 |
| `dentalClinic_counters` | これまでに発行したIDの最大番号（例：`{"P": 9, "V": 29}`）。削除したIDを再利用しないために使用 |
| `dentalClinic_questionnaires` | 初診問診票の配列 |

### 患者（patients）

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | 文字列 | 患者ID（例：`P0001`）。一意 |
| `name` | 文字列 | 氏名（必須） |
| `kana` | 文字列 | フリガナ |
| `birthDate` | 文字列 | 生年月日（`YYYY-MM-DD`） |
| `gender` | 文字列 | 性別（`男性` / `女性` / `その他` / 空欄） |
| `phone` | 文字列 | 電話番号 |
| `address` | 文字列 | 住所 |
| `firstVisitDate` | 文字列 | 初診日（`YYYY-MM-DD`） |
| `note` | 文字列 | 備考 |
| `createdAt` / `updatedAt` | 文字列 | 登録・更新日時（ISO 形式。画面から登録したデータのみ） |

### 来院記録（visits）

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | 文字列 | 記録ID（例：`V0001`）。一意 |
| `patientId` | 文字列 | 対象患者の患者ID（患者との紐付け） |
| `date` | 文字列 | 来院日（`YYYY-MM-DD`） |
| `complaint` | 文字列 | 主訴・症状 |
| `treatment` | 文字列 | 診療内容 |
| `doctor` | 文字列 | 担当医 |
| `fee` | 数値 | 費用（円、0 以上の整数） |
| `note` | 文字列 | 備考 |
| `createdAt` / `updatedAt` | 文字列 | 登録・更新日時 |

### 初診問診票（questionnaires）

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | 文字列 | 受付ID（例：`Q1791526228726`。送信時刻から作成） |
| `submittedAt` | 文字列 | 受付日時（ISO 形式） |
| `status` | 文字列 | 受付状況：`unconfirmed`（未確認）／`confirmed`（確認済み）／`registered`（患者登録済み） |
| `patientId` | 文字列 | 登録・紐付けした患者の患者ID（未登録の間は `null`） |
| `answers` | オブジェクト | 回答内容（氏名・来院目的・症状・健康状態など） |
| `confirmedAt` / `registeredAt` | 文字列 | 確認・登録した日時 |

### 患者と来院記録・問診票の関係

```
患者 P0001 ──┬── 来院記録 V0001（patientId: P0001）
             ├── 来院記録 V0002（patientId: P0001）
             └── ...
```

1 人の患者に対して、複数の来院記録が `patientId` で紐付きます（1 対多）。
問診票も同じように `patientId` で患者と紐付きますが、来院記録とは別のデータとして保存します。
**最終来院日・来院回数・累計診療費は保存せず**、表示のたびに来院記録から計算します。
そのため、記録を追加・編集すると常に正しい値が表示されます。

## 5. 使用方法

1. `index.html` をダブルクリックしてブラウザで開きます。
   初回はデモデータ（架空の患者 8 名）が表示されます。
2. **新しい患者を登録する**：右上の「新規患者登録」→ 入力 →「登録」。
3. **患者を探す**：検索欄に氏名・フリガナ・患者IDの一部を入力します（例：`山田`、`P0001`）。
4. **基本情報を直す**：氏名をクリック →「基本情報を編集」→「更新」。
5. **来院を記録する**：患者詳細で「＋ 来院記録を追加」→ 入力 →「保存」。
6. **来院記録を直す**：来院履歴の各行の「編集」→「保存」。
7. **来院記録を削除する**：来院履歴の各行の「編集」→ 画面の一番下の「この来院記録を削除」→ 確認で「OK」。
8. **初期状態に戻す**：患者一覧の下の「デモデータに戻す」→ 確認で「OK」（問診票も削除されます）。
9. **問診票を入力する（患者さん）**：`questionnaire.html` を開き、回答 →「入力内容を確認する」→「送信する」。
   `questionnaire.html?demo=1` で開くと、架空データの入力ボタンが使えます。
10. **問診票を受け付ける（受付スタッフ）**：患者一覧の「問診票受付」→ 氏名をクリック → 内容を確認 →「患者として登録」（同じ方が登録済みの場合は「この患者に紐付ける」）。
   ※ 問診票と管理画面は、同じ端末・同じブラウザで開いてください。

### データの確認・削除（開発者向け）
ブラウザの開発者ツール（`F12`、Mac は `Cmd + Option + I`）→「Application」→「Local Storage」で、上記のキーを確認・削除できます。

## 6. 現在の制約

- **セキュリティ**：ログイン機能・アクセス制御・暗号化がありません。同じパソコンとブラウザを使う人は誰でもデータを閲覧できます。
- **保存先**：データはブラウザごと・パソコンごとに別々です。他の端末とは共有できません。ブラウザの閲覧データを削除すると、データも消えます。
- **容量**：localStorage の容量（一般的に 5MB 程度）を超えるデータは保存できません。
- **同時利用**：複数のタブで同時に編集すると、後から保存した内容で上書きされることがあります。
- **削除機能**：患者の削除機能はありません。来院記録の削除は完全削除（復元不可）です。
- **重複登録**：「新規患者登録」画面では、同じ患者を二重に登録しても警告は表示されません（問診票からの登録時のみ重複を確認します）。
- **問診票**：問診票は同じ端末・同じブラウザの管理画面にのみ反映されます。患者さん自身のスマートフォンからの送信には対応していません。
- **バックアップ**：データの書き出し・読み込み機能はありません。
- **保険診療**：保険点数計算、負担割合、レセプト（診療報酬明細書）には対応していません。費用は窓口で受け取った金額を手入力します。
